# Rubric: is this a good first issue?

## Checks

| Check                               | Evidence                                                                                                                                                                               | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                 | Weight   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Maintainer alive                    | The `"last 5 default-branch commits"` and `"maintainer first-response sample"` in the repo-facts block, plus maintainer/owner/member/collaborator activity in the issue comment thread | Pass if there is at least one non-bot default-branch commit within the last 12 months **or** at least one maintainer first response within the last 1 month. Bot-only activity does not count.                                                                                                                                                                                                                                               | required |
| Repository in use                   | The repo-facts `"archived:"`, `"last 5 default-branch commits"`, and `"latest release"` fields                                                                                         | Pass if the repository is not archived and there is at least one non-bot default-branch commit or release within the last 3 months.                                                                                                                                                                                                                                                                                                           | required |
| Scope fits a newcomer | The issue body and comment thread; scope guidance in `references/evidence-guide.md` | Pass if the issue describes a reasonably clear bug, task, documentation change, cleanup, or feature request that a contributor could act on. The exact implementation does not need to be specified. A bug passes when its affected behavior or causes are clearly identified, even if the issue lists multiple possible fixes or implementation approaches. Fail if it is an umbrella/tracking issue, a pure usage/support question, an unresolved design or product decision, or explicitly requires broad/core-internal changes. Multiple suggested approaches, technical investigation, or related implementation changes do not by themselves make an issue out of scope. If the intended problem or outcome is genuinely unclear after reading the issue and thread, grade unclear. | required |


| Nobody is already working on it | The issue `"assignees"` field in repo facts, linked PRs in repo facts, and the issue comment thread | Pass if there is no assignee, no open linked PR, and no current claim or in-progress comment such as “I'll take this,” “can I work on this,” or “working on this.” Any open linked PR is evidence that someone is actively working on the issue and fails this check. A closed or abandoned PR does not fail by itself. An old claim does not fail if there is no evidence of current work, but a recent claim or explicit statement of ongoing work fails. When the issue thread and sidebar disagree, use the thread's more recent evidence. | required |

| Contribution policy allows the work | The repository's contribution policy and AI policy files, using the `"contribution policy"` field in repo facts | **Fail if the contribution policy explicitly prohibits AI-generated code or documentation. Pass otherwise.** Requirements to disclose AI use, personally understand the contribution, test it, or have a human review it are not prohibitions and pass. If the repo-facts contribution policy contains an explicit AI prohibition, this check must fail regardless of the issue's scope, age, labels, or other checks. | required |

## Verdict rule

Accept if and only if every required check passes.

Reject if any required check fails.

Unclear counts as fail.

Preferred checks are not used in this rubric; every check above is required because each represents a condition that can independently make an issue unsuitable for a first contribution.
