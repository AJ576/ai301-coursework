# PR precheck rubric

Grade the candidate PR package against the issue, the plan it claims to implement, and the repository's submission requirements. Use the evidence sources and pass conditions below; `references/evidence-guide.md` says where each one lives. `required` checks decide readiness; `preferred` checks are reported but never change the verdict.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity (`silent-drift`) | The diff's changed files and hunks read against the plan's stated scope, not-in-scope items, and deviation notes; the description's claims read against the diff | Every changed file and hunk is inside the plan's scope, is a test for it, or is named in a deviation note with a reason. Every item the plan commits to is in the diff, or is explicitly deferred in the plan's note and the description. Fail if the diff adds unplanned behavior (a new option, flag, setting, rename pass, or rewrite of code the plan never names), drops a planned item with no note, or the description claims something the diff does not contain (for example "implements the plan exactly" or "docs now document X" when they do not). Deferring an adjacent problem with a stated reason is not drift. | required |
| Test evidence (`not-tested`) | The test-evidence section read against the plan's test plan and repro evidence; the repo's own required checks; test files in the diff | The deciding question is whether the plan's own repro (the failing case, not a control case that never broke) is re-run with an observable before showing the bug and an after showing the expected behavior. Pass when it is, every failure mode the test plan names is shown, and the repo's suite is reported by its command and outcome (a one-line summary such as "`cargo test -p ignore` passes (214 tests)" is enough; full output is not required). Controls stated as unchanged need no separate output. Fail when the repro is never shown before and after ("tested locally", "works on my machine", "colors work now"), when the evidence runs only a path that never broke, or when a failure mode the test plan names is not re-run. A check reported honestly as not run or failing, with a concrete reason, does not fail this row by itself. | required |
| Diff quality (`unreviewable`) | Every hunk of the unified diff and every commit message | Every hunk is the fix or its test. Fail if the diff contains any debris: a debug print or log line, commented-out code or an abandoned first attempt, a dead or unused function, a TODO added in the diff, formatting-only or re-indent churn, an import reshuffle unrelated to the fix, whole blocks of statements removed and re-added unchanged, or an edit to an unrelated file. Unchanged lines that a diff re-prints because they belong to the same statement as a real edit (for example the opening lines of a multi-line call whose argument changed) are not churn; judge the statement, not each line. In live mode, also fail if plan.md, comment.md, pr_draft.md, or test_evidence.md is in the diff. A correct fix does not excuse debris. | required |
| Standards and comms (`standards-wall`) | The repo-facts PR template asks and contribution or AI policy (live: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`) read against the title, description, and diff | Every section and checklist item the repo's template requires has real content, including an issue link ("Closes #N") where asked, and any required changelog or whatsnew file is in the diff. Where the repo's policy requires AI-use disclosure, the description states the tool and the extent of help. Treat every package as AI-assisted, so a missing disclosure fails. If the repo states no template and no policy, this check passes on that point; never invent a requirement. | required |
| Title and description clarity | The PR title and the description's summary read against the diff | The title names the specific behavior changed, not just "fix bug", and the summary says what changed and why in terms a reviewer can check against the diff. | preferred |

## Verdict rule

Return `accept` only when every `required` check passes. Return `reject` if any `required` check is `fail` or `unclear`. An `unclear` grade counts as a fail: a claim that cannot be verified from the package is not ready to submit. `preferred` checks never change the verdict.

**Clear-accept guard.** Do not fail a check for how the PR looks. A terse description, a one-line diff, few commits, or a plain title is not a failure if the fix matches the plan, the evidence is observable, the diff is clean, and the repo's stated asks are met. Grade the artifact, not its length or polish.

**Honest-outcome rule.** A PR that openly discloses a shortfall can be ready. If a planned item is deferred, and both the plan's note and the description say so with a reason, that is not silent drift. If a check could not be run and the evidence says so with the reason, that does not fail test evidence on its own. Honesty does not turn missing *required* evidence into a pass: the plan's own repro must still be shown before and after.
