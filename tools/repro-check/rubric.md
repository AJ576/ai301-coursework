# Rubric: is this reproduction package ready to post?

## Checks

| Check                | Evidence                                                                                                                      | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Weight   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| behavior-matches     | The repro report's observed output, error, log, or other artifact, read against the issue description and the stated trigger  | Pass if the report demonstrates the issue's reported behavior, **or** if it honestly reports that the issue could not be reproduced and the evidence shows that the relevant trigger was actually attempted. A different or adjacent error must not be presented as the issue being reproduced.                                                                                                                                                                                                                | required |
| environment-recorded | The repro report's environment record, read against the issue's stated version/platform target                                | Pass if the report identifies the relevant software/project version or commit and operating system/platform, plus any runtime version needed to interpret or repeat the reproduction. If the tested environment differs from the issue's target, the difference must be stated rather than silently omitted.                                                                                                                                                                                                   | required |
| steps-reproducible   | The reproduction steps, commands, inputs, setup, and any referenced files in the repro report                                 | Pass if another person with the stated environment and required project state could understand and repeat the attempted trigger without guessing a command, input, file, or setup detail that could affect the outcome. For a cannot-reproduce report, the steps only need to establish a concrete attempt at the issue's relevant trigger; they do not need to reproduce the bug or exactly duplicate the reporter's setup when the report clearly identifies the relevant environmental or setup difference. | required |
| honest-conclusion    | The repro report's conclusion, read against its reported steps and evidence                                                   | Pass if the conclusion says what the evidence actually demonstrates. A reproduced issue must not be claimed when the evidence shows a different result; an honest cannot-reproduce conclusion passes when the attempted trigger and observed result support it.                                                                                                                                                                                                                                                | required |
| comms-compliant      | The claim comment and repro report, read against the repo-facts block's bug-report/contribution conventions and AI-use policy | Pass if the comments follow any stated repository requirements that apply to these comments, including required information and AI-use disclosure when the repo requires it. Missing or contradicting an explicit repo convention fails.                                                                                                                                                                                                                                                                       | required |

## Verdict rule

Accept if every required check passes. Preferred checks, if added later, never change the verdict. Any `unclear` result on a required check counts as fail. The verdict is binary: accept or reject.
